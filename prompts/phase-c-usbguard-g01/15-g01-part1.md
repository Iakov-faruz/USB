# פרומפט 15 — בדיקות התנהגות G-01 חלק א` (Gate G-01 Tests Part 1)

## מטולה
שער אימות חובה חלק א`. בדיקות התנהגות בסיסיות של USBGuard בסביבת מעבדה בלבד. לא לדלג עליו וללא סימון PASS ללא ראיות.

## קבצים צפויים
`docs/g01-report-part1.md` (דוח בדיקות)

## קריטריון אימות
בדוק שהדוח כולל את כל הניסויים, תנאי הסביבה, פקודה, פלט, קוד יציאה, ראיות ומסקנה לכל אחד.

## מה לומדים
איך לבדוק שהפקודות של USBGuard מתנהגות כמו שאתה מצפה.

---

```text
PROMPT 15 — Gate G-01 Tests Part 1

LAB ENVIRONMENT ONLY. Do not run on development host.

Execute the following tests in an isolated VM with USB passthrough only.
Before every policy-changing test, verify lab identity, recovery path,
baseline device/policy state, and that no production device is at risk.

1. Check usbguard version, distribution, and available CLI commands.
2. Check daemon configuration: RuleFile vs RuleFolder and protected system rules.
3. Test append-rule separately from approval of an already-connected device.
4. Test temporary rule addition/removal and verify current Rule ID is located
   and matched immediately before removal.
5. Test permanent rule persistence and whether the command also changes the
   connected device state.
6. Test whether adding a rule affects already-connected devices.

For each test, record lab verification, exact command, before/after state,
output, exit code, evidence, conclusion, and PASS/FAIL/UNVERIFIED:
Do NOT proceed to Part 2 with missing or ambiguous evidence.
Return test report.
```

## משימות מפורטות

### לפני בדיקות שמשנות policy
- אמת את זהות סביבת המעבדה.
- הצג את גרסת USBGuard ואת תצורת ה-daemon.
- בדוק את מצב ההתקנים והכללים לפני כל ניסוי.
- ודא שהבדיקה לא תנתק התקן חיוני או תשנה את מחשב העבודה.
- ודא שיש מסלול התאוששות.
- אם אחד התנאים אינו מתקיים, עצור.

### בדוק את הנושאים הבאים (חלק א`)
1. בדוק usbguard version, הפצה ופקודות CLI זמינות.
2. בדוק תצורת דמון: RuleFile לעומת RuleFolder.
3. בדוק בנפרד הוספת כלל זמני, אישור התקן מחובר, ומצב לאחר כל פעולה.
4. אתר Rule ID עדכני, אמת שהכלל תואם, הסר אותו ואמת שנעלם.
5. הוסף כלל קבוע, אמת היכן נשמר והאם הפקודה גם אישרה התקן מחובר.

עבור כל בדיקה, רשום:
- פקודה מדויקת
- פלט
- קוד יציאה
- מסקנה

אל תעבור לחלק ב` עד שהבדיקות אומתו.
החזר דוח בדיקות.

## תיקון קריטי (חובה)

- אל תניח ש-`allow-device --permanent` ו-`append-rule` הן פעולות בלתי תלויות שאפשר תמיד לבצע ברצף. הפעולה הראשונה עשויה גם לאשר את ההתקן וגם להוסיף כלל קבוע.
- אל תניח ש-`remove-rule` מקבל hash במקום Rule ID.
- אל תניח שהסרת כלל זמני חוסמת את ההתקן.

## ערך החזרה

דוח G-01 חלק א` שניתן לעקוב אחריו. אין להציג מסקנות שלא נבדקו בפועל.

## איסורים

- אם אין VM מבודד, USB passthrough, מסלול התאוששות או ראיות חד-משמעיות, סמן `G-01 = UNVERIFIED` ועצור לפני מימוש פעולות תלויות.
- אין להצהיר על G-01 כ-PASS אם חסר ניסוי חובה.
