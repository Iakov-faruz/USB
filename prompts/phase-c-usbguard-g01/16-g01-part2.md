# פרומפט 16 — בדיקות התנהגות G-01 חלק ב` (Gate G-01 Tests Part 2)

## מטרה
איך לבדוק מקרי קצה והתנהגות לאחר הפעלה מחדש. המשך ישיר לחלק א`.

## קבצים צפויים
`docs/g01-report-part2.md`, `docs/g01-final-report.md`

## קריטריון אימות
בדוק שהדוח הכולל כולל סטטוס סופי (PASS/FAIL/UNVERIFIED).

## מה לומדים
איך לבדוק מקרי קצה והתנהגות לאחר הפעלה מחדש.

---

```text
PROMPT 16 — Gate G-01 Tests Part 2

LAB ENVIRONMENT ONLY.

Execute the following tests and document results:

1. Test: Rule precedence — add block rule, then allow rule, check which wins.
2. Test: Remove rule with current Rule ID (not cached ID).
3. Test: Behavior after daemon restart.
4. Test: Behavior after reboot with positive, verified time synchronization.
5. Test: Behavior after reboot with synchronization missing or clock jump.
6. Test: Identify the target time synchronization provider and exact status
   fields/values. Verify missing or unsupported status fails closed.
7. Test: What happens when IPC is unavailable.
8. Test: In the isolated VM, call block-device for a disposable connected
   device with no independent allow rule. Verify the device state changes to
   blocked, unrelated devices are unchanged, and the operation is not confused
   with adding/removing a persistent rule.

For each test, first verify isolated VM and recovery path. Record:
- Exact command sequence
- State before and after
- Exit codes
- Time-sync evidence/provider where applicable
- Lab/USBGuard version and evidence
- Conclusion

For each test, mark PASS only if observed behavior meets the SRS safety
criterion; mark FAIL when evidence proves behavior violates it; use
UNVERIFIED only when evidence is missing or ambiguous. A failing mandatory
criterion blocks dependent implementation.
```

## משימות מפורטות

עבור את הבדיקות הבאות במעבדה בלבד:

1. בדיקה: קדימות כללים — הוסף כלל חסימה, אחריו כלל אישור, בדוק מי מנצח.
2. בדיקה: הסר כלל עם Rule ID עדכני (לא מזומן).
3. בדיקה: התנהגות לאחר הפעלה מחדש של הדמון.
4. בדיקת reboot כאשר מקור הזמן מדווח סנכרון חיובי ואמין.
5. בדיקת reboot כאשר הסנכרון חסר, לא נתמך או קפיצת שעון זוהתה.
6. תעד את מקור סנכרון הזמן, הפקודה, השדות/ערכים הצפויים, וטיפול במידע חסר.
7. בדיקה: מה קורה כאשר IPC אינו זמין.
8. בדיקה במעבדה בלבד: הפעל `block-device` על התקן מחובר חד-פעמי ללא כלל
   מתיר עצמאי; אמת שההתקן נחסם, התקנים אחרים לא השתנו, ולא השתנתה מדיניות
   מתמידה. תעד את הפקודה והתוצאה המדויקת.

עבור כל בדיקה, רשום:
- רצף פקודות מדויק
- מצב לפני ואחרי
- קודי יציאה
- מסקנה

רכז דוח G-01 סופי עם סטטוס PASS/FAIL/UNVERIFIED לכל בדיקה. PASS רק כאשר ההתנהגות שנצפתה עומדת בקריטריון הבטיחות של ה-SRS; FAIL כאשר הראיות מוכיחות חריגה; UNVERIFIED רק כאשר חסרות ראיות או שהן עמומות. כישלון בקריטריון חובה חוסם עבודה תלויה.

## ערך החזרה

דוח G-01 סופי כולל סטטוס סופי. אין לטעון PASS אם בדיקה חובה חסרה.

## איסורים

- בדיקות אלה ירוצו בסביבת מעבדה מבודדת בלבד.
- אל תסמן PASS אם ראיות חסרות.
